# 관리자 로그인

루트 앱 상단의 **관리자 로그인**은 `/admin`으로 이동합니다. 이 릴리스는 로그인·로그아웃·서버에서 검증되는 전용 화면의 기반만 제공합니다. 현장 상태 수정, 사진 검수, 기도 수신함, 나눔 관리와 실제 개인정보 저장은 **아직 연결되지 않았습니다**. 기존 `/app`의 Supabase 운영자 인증과는 별도이며, 이 로그인은 기존 Supabase 권한을 우회하거나 부여하지 않습니다.

## 서버 환경변수

아래 값은 Vercel **Production / Secret** 환경변수로만 설정합니다. `VITE_` 접두사, 소스코드, README, PR, 테스트, 프런트 번들에 실제 계정이나 키를 넣지 않습니다. Preview는 별도 테스트 설정을 넣지 않으면 503으로 닫힙니다.

| 이름 | 용도 |
| --- | --- |
| `ADMIN_LOGIN_ID` | 관리자 아이디. 앞뒤 공백과 영문 대소문자는 구분하지 않음 |
| `ADMIN_PASSWORD_SCRYPT` | `scrypt$<16-byte salt hex>$<32-byte derived key hex>` 형식. N=16384, r=8, p=1. 비밀번호 원문은 저장하지 않음 |
| `ADMIN_SESSION_SECRET` | 암호학적 난수 48바이트를 base64url로 인코딩한 64자 이상 서명 키 |
| `ADMIN_ALLOWED_ORIGIN` | 로그인·로그아웃을 허용할 정확한 HTTPS origin |

환경변수를 바꾼 뒤 새 배포가 필요합니다. 비밀번호를 변경하거나 모든 기기의 세션을 폐기할 때는 **세션 서명 키도 함께 교체**합니다. 이 저장소에는 실제 설정값이 없습니다.

## API와 보안 경계

- `POST /api/admin/login`: JSON 아이디·비밀번호를 서버에서 scrypt/상수 시간 비교로 검증합니다. 로그인 성공 시 쿠키를 새로 발급합니다. 잘못된 아이디와 비밀번호는 동일한 오류를 반환합니다.
- `GET /api/admin/session`: 유효한 서버 서명이 있는 쿠키만 허용합니다.
- `GET /api/admin/dashboard`: 인증 없이는 401. 현재는 로그인 계정·만료 시각과 **모두 false인** 기능 연결 상태만 반환합니다.
- `POST /api/admin/logout`: 동일 origin JSON 요청만 허용하고 브라우저 쿠키를 만료시킵니다. 로그아웃 API 응답의 `authenticated: false`가 확인돼야 화면도 로그아웃됩니다.
- 세션은 HMAC-SHA256 서명, 2시간 만료, 무작위 nonce를 사용합니다. `__Host-woori_admin` 쿠키는 `HttpOnly; Secure; SameSite=Strict; Path=/`이며 Domain 속성이 없습니다.
- 브라우저 localStorage/sessionStorage, 임의 변수, URL, UI 상태는 인증 근거가 아닙니다. 프런트가 변경돼도 보호 API의 서버 검증은 남습니다.
- API 응답은 `private, no-store`; `/admin`도 캐시하지 않고 검색 인덱싱을 막습니다. 서비스 워커는 관리자 경로와 모든 API를 가로채지 않습니다.
- POST는 정확한 Origin과 JSON 형식을 요구합니다. 요청 본문 크기를 제한하고, 인증 API의 다른 경로 표기는 거부합니다.
- 이 세션은 **stateless**입니다. 로그아웃은 해당 브라우저의 쿠키를 지우지만, 이미 탈취된 쿠키 사본을 중앙에서 개별 폐기하지는 못합니다. 사본은 만료 또는 서명 키 교체 시 무효화됩니다. 중앙 폐기·감사 기능이 필요한 실제 운영 단계에서는 영속 세션 저장소를 도입해야 합니다.

## 반복 시도와 브라우저 확인

운영 프로젝트의 Vercel Firewall에 다음 규칙을 별도로 게시합니다. `vercel.json`만으로 이 규칙이 설치되지는 않습니다.

- 이름: `Admin browser verification`
- 조건: Request Path / Matches expression / `^/(admin(/.*)?|api/admin/.*)$`
- 동작: **Challenge**
- 일반 예배·주차·나눔 화면에는 적용하지 않습니다. 새로운 유료 Rate Limit 기능이나 관리형 규칙 패키지는 활성화하지 않습니다.

브라우저 보안 확인을 통과한 뒤 같은 브라우저에서 API를 이용합니다. 확인 세션이 만료되어 AJAX가 막히면 관리자 화면의 **관리자 페이지 다시 열기**로 전체 페이지를 다시 열어 확인합니다. 보안 확인은 관리자 로그인 자체를 대신하지 않습니다.

애플리케이션은 같은 연결 식별자에서 15분 안에 5회 실패하면 429를 반환합니다. 이 보조 제한은 **서버리스 인스턴스 메모리에만 존재**하므로 재시작·여러 인스턴스·분산 공격을 통틀어 누적하는 제한이 아닙니다. 브라우저 Challenge도 정교한 브라우저 공격을 완전히 막는 기능은 아닙니다.

**짧은 숫자 비밀번호를 실제 개인정보·사진·기도 관리의 장기 인증 수단으로 사용하지 않습니다.** 실데이터 관리 기능을 연결하기 전에는 충분히 긴 비밀번호와 영속/분산 시도 제한, 필요 시 MFA·중앙 세션 폐기·감사 기록을 추가해야 합니다. 지금은 수집/수정 기능이 서버에서 비활성 상태입니다.

## 검증

```sh
npm run lint
npm test
npm run test:server
npm run build
node --check public/sw.js
```

서버 테스트는 임의의 전용 fixture 계정만 사용하며 실제 비밀번호는 참조하지 않습니다. 구성 누락, 잘못된 계정, 잘못된 Origin, 요청 크기/형식, 경로 우회, 서명 위조, 중복 쿠키, 세션 만료, 서명 키 교체, warm-instance 시도 제한과 로그아웃을 검사합니다. UI는 로그인 상태 확인, 보호 API 오류 시 닫힘, 입력 중 포커스 유지, 로그아웃과 늦게 도착한 응답의 경합을 검사합니다.
